# QQ Setting 交互设计文档

## 概述

`/qq setting` 是 EchoAgentPanel 中 QQ 适配器管理的核心界面，提供门控模式切换、白名单/黑名单管理等功能。本文档从抽象层面定义其交互逻辑、状态管理和用户体验设计。

## 交互流程

### 1. 主设置界面

#### 入口与触发
- **命令路径**: 用户输入斜杠命令 → 命令解析 → 功能分发
- **命令格式**: `/qq setting`
- **权限要求**: 需要QQ适配器连接状态

#### 界面结构

```
┌─ QQ 设置 (位置指示) ──────────────────────┐
│                                              │
│  ── 门控模式（互斥，选一） ──              │
│  ● 当前选中模式 (单选状态)                  │
│  ○ 其他可选模式 (单选状态)                  │
│                                              │
│  ── 名单管理 ──                            │
│  🔒 管理白名单                               │
│  🚫 管理黑名单                               │
│                                              │
│  ── 操作提示 ──                             │
│  导航和确认操作说明                          │
└──────────────────────────────────────────────┘
```

#### 交互规则

| 按键 | 功能 | 行为说明 |
|---|---|---|  
| ↑↓ | 选择导航 | 在选项间移动，自动滚动保持选中项可见 |
| Home | 跳转开头 | 直接定位到第一个选项 |
| End | 跳转末尾 | 直接定位到最后一个选项 |
| Enter | 确认选择 | 执行当前选中项的操作 |
| e | 快捷确认 | 与Enter功能相同，提供便捷操作 |
| Esc | 退出返回 | 返回上一级或完全退出 |

#### 门控模式切换逻辑

**状态互斥原则**: 三种门控模式互斥，同时只能激活一种

**切换流程**:
1. 用户选中目标模式
2. 系统解析当前选项对应的模式类型
3. 向后端发送模式切换命令
4. 等待后端确认并更新状态
5. 刷新界面显示新模式状态

**模式定义**:
- **无约束**: 所有人都可以使用Agent
- **白名单**: 仅白名单用户/群组可以使用Agent
- **黑名单**: 黑名单用户/群组禁止使用Agent

### 2. 白名单/黑名单管理界面

#### 入口路径
- **白名单**: 主设置界面 → 选择"管理白名单" → 白名单管理界面
- **黑名单**: 主设置界面 → 选择"管理黑名单" → 黑名单管理界面

#### 界面布局

```
┌─ QQ 名单管理 (位置指示) ─────────────────┐
│                                               │
│  ── 当前名单用户 (数量) ──                 │
│    👤 现有用户列表项                         │
│    ➕ 手动添加用户 (操作提示)               │
│                                               │
│  ── 名单群列表 (操作提示) ──                │
│    [✓] 已加入群组 (QQ号和群名)              │
│    [ ] 未加入群组 (QQ号和群名)              │
│                                               │
│  ── QQ好友列表 (操作提示) ──               │
│    [✓] 已添加好友 (昵称和QQ号)              │
│    [ ] 未添加好友 (昵称和QQ号)              │
│                                               │
│  ── 状态提示 ──                             │
│  当前名单模式的行为说明                      │
│                                               │
│  ── 操作说明 ──                             │
│  导航和操作提示                              │
└───────────────────────────────────────────────┘
```

#### 数据加载策略

**智能缓存机制**:
- **首次进入**: 请求完整数据并缓存
- **再次进入**: 优先使用缓存，仅在必要时更新
- **数据为空**: 主动重试获取数据
- **加载失败**: 标记加载状态，避免无限重试

**分层请求**:
1. 请求当前配置状态 (总是需要)
2. 请求群组列表 (仅在未缓存时)
3. 请求好友列表 (仅在未缓存且为空时)

#### 交互操作分类

**导航操作**:
| 操作 | 功能 | 视觉反馈 |
|---|---|---|
| ↑↓ | 选项导航 | 高亮当前选项，自动滚动 |
| Home | 跳到开头 | 定位到第一个项目并滚动 |
| End | 跳到末尾 | 定位到最后一个项目并滚动 |

**执行操作**:
| 选中项类型 | 触发键 | 行为描述 |
|---|---|---|
| 门控模式选项 | Enter/e | 切换到该门控模式 |
| 管理入口选项 | Enter/e | 进入对应的管理界面 |
| 群组列表项 | Enter/e | 切换群组在名单中的加入状态 |
| 好友列表项 | Enter/e | 切换好友在名单中的添加状态 |
| 手动添加用户 | Enter/e | 进入QQ号输入编辑模式 |
| 现有用户项 | Enter/e | 从名单中移除该用户 |

#### 自适应滚动机制

**动态视口计算**:
- 根据总项目数量自适应调整可见区域大小
- 最小显示5个项目，最多显示15个项目
- 根据终端高度动态调整

**智能滚动逻辑**:
1. 用户选择项目时检查是否在可见范围内
2. 如果选中的项目在可见区域上方，向上滚动
3. 如果选中的项目在可见区域下方，向下滚动
4. 确保当前选中的项目始终保持在可见区域内

**滚动指示器**:
- 上方有未显示内容: 显示向上箭头提示
- 下方有未显示内容: 显示向下箭头提示
- 所有内容可见: 不显示滚动指示器

### 3. 手动添加QQ号编辑模式

#### 触发条件
- **前置状态**: 在白名单/黑名单管理界面
- **选择动作**: 选中"➕ 手动添加用户"选项
- **确认操作**: 按Enter或e键触发编辑模式

#### 界面状态

```
┌─ 编辑QQ号 (位置指示) ─────────────────────┐
│                                             │
│  ▸ QQ号: [输入框]                          │
│                                             │
│  操作提示说明                                │
└─────────────────────────────────────────────┘
```

#### 编辑交互

| 输入操作 | 功能 | 系统响应 |
|---|---|---|
| 数字/字符 | 输入QQ号 | 实时显示输入内容 |
| Backspace | 删除字符 | 移除最后输入的字符 |
| Enter | 确认提交 | 验证并处理QQ号 |
| Esc | 取消操作 | 退出编辑模式 |

#### 提交验证流程

**输入验证**:
1. 检查输入是否为空
2. 验证是否为有效的数字格式
3. 检查是否为合理的QQ号范围

**重复检查**:
1. 解析当前名单类型 (白名单/黑名单)
2. 查询目标名单中是否已存在该QQ号
3. 如果已存在，提示用户并保持在编辑模式
4. 如果不存在，执行添加操作

**添加执行**:
1. 更新本地名单数据
2. 发送后端更新命令
3. 等待后端确认
4. 刷新界面显示最新状态
5. 显示操作成功提示

#### 错误处理场景

| 错误类型 | 检测时机 | 用户提示 | 恢复策略 |
|---|---|---|---|
| 空输入 | 提交时 | "请输入QQ号" | 保持编辑模式 |
| 格式错误 | 提交时 | "无效的QQ号，请输入数字" | 保持编辑模式 |
| 重复添加 | 验证时 | "用户已在名单中" | 保持编辑模式 |
| 网络错误 | 执行时 | "操作失败，请重试" | 退出编辑模式 |

## 状态管理

### 状态层次结构

**应用级状态**:
- 当前激活的门控模式
- QQ适配器连接状态
- 全局配置缓存

**界面级状态**:
- 当前显示的界面类型
- 表单激活状态
- 用户选择索引

**数据级状态**:
- 白名单数据 (用户+群组)
- 黑名单数据 (用户+群组)
- 群组列表缓存
- 好友列表缓存
- 数据加载状态标记

### 状态转换模型

```
[主设置界面]
       ↓ 选择名单管理
[名单管理界面] ←─────┐
       ↓ 编辑操作      │ 数据更新事件
[编辑模式]            │
       ↓ 提交确认      │ 自动刷新触发
[名单管理界面] ───────┘
       ↓ 返回操作
[主设置界面]
```

**转换条件**:
- **前进**: 用户主动选择并确认
- **返回**: 用户按Esc或完成操作
- **刷新**: 接收到后端数据更新事件
- **错误**: 操作失败时保持当前状态

### 数据同步机制

**单向数据流**:
1. **请求阶段**: 界面 → 请求命令 → 后端处理
2. **响应阶段**: 后端 → 数据事件 → 界面更新
3. **缓存更新**: 接收数据 → 更新缓存 → 刷新显示

**一致性保证**:
- 所有名单修改通过后端确认后生效
- 本地缓存仅用于显示，不作为权威数据源
- 操作失败时保持原状态，不进行本地预更新

## 通信协议

### 请求类型

**配置请求**:
- 获取当前门控模式
- 获取白名单配置
- 获取黑名单配置

**数据请求**:

- 获取QQ好友列表

**更新请求**:
- 设置门控模式
- 更新白名单 (用户+群组)
- 更新黑名单 (用户+群组)

### 事件类型

**配置事件**:
- 门控模式变更通知
- 名单配置变更通知

**数据事件**:
- 群组列表数据更新
- 好友列表数据更新

**错误事件**:
- 连接失败通知
- 操作失败通知
- 超时通知

## 性能优化

### 防抖机制

**刷新防抖**:
- 短时间内多次刷新请求合并为一次
- 防抖时间窗口: 500毫秒
- 确保最终状态一致性

**请求防抖**:
- 相同请求在短时间内不重复发送
- 已发出的请求未完成前不发新请求

### 缓存策略

**分级缓存**:
- **L1缓存**: 当前界面显示数据
- **L2缓存**: 全局数据副本
- **L3缓存**: 后端权威数据

**缓存失效**:
- 用户主动刷新操作
- 检测到数据不一致
- 超过缓存有效期

### 加载优化

**渐进式加载**:
- 先显示界面框架
- 再填充实际数据
- 最后更新交互状态

**状态指示**:
- 未加载: 显示加载提示
- 加载中: 显示进度提示
- 加载完成: 显示实际数据
- 加载失败: 显示错误状态

## 用户体验

### 加载状态设计

**状态转换**:
```
[初始状态] → [加载中] → [完成] / [失败]
     ↓          ↓          ↓
显示框架   显示进度   显示数据/错误
```

**状态指示**:
- **加载中**: "正在获取数据…" (带动画)
- **已完成**: 显示实际数据
- **已失败**: "暂无数据，或连接失败"

### 视觉反馈系统

**选择状态**:
- **当前选中**: 高亮显示 + 定位符 (▸)
- **单选状态**: 实心圆 (●) / 空心圆 (○)
- **复选状态**: 勾选框 ([✓]) / 空框 ([ ])

**位置指示**:
- 显示当前位置: "当前位置/总数量"
- 滚动状态: 上下箭头指示
- 边界状态: 首项/末项高亮提示

**操作反馈**:
- **成功提示**: 绿色背景 + 成功图标
- **错误提示**: 红色背景 + 错误图标  
- **信息提示**: 黄色背景 + 信息图标

### 错误恢复机制

**用户友好错误处理**:
1. **明确错误原因**: 用用户可理解的语言描述问题
2. **提供解决建议**: 告诉用户如何解决问题
3. **保持可用状态**: 错误后仍可继续操作
4. **允许重试操作**: 提供重新尝试的机会

**错误分类处理**:
- **连接错误**: 提示检查QQ登录状态
- **权限错误**: 提示检查操作权限
- **格式错误**: 提示输入格式要求
- **网络错误**: 提示网络连接问题

## 可访问性设计

### 键盘导航

**完整导航支持**:
- 方向键: 上下左右完整支持
- 快捷键: Home/End快速跳转
- 确认键: Enter/e双键支持

**导航一致性**:
- 所有界面使用相同的导航模式
- 相同按键在不同界面有相同功能
- 提供清晰的操作提示

### 视觉可访问性

**对比度设计**:
- 高对比度标识当前选中项
- 不同状态使用不同颜色标识
- 确保在各种终端主题下清晰可见

**信息层次**:
- 主要信息使用明亮颜色
- 次要信息使用柔和颜色
- 辅助信息使用暗淡颜色

**状态明确性**:
- 使用符号和文字双重指示状态
- 提供位置信息和进度提示
- 显示可操作项的预期行为

### 操作安全性

**防误操作**:
- 重要操作需要确认步骤
- 提供撤销机制
- 不可逆操作前给出警告

**状态恢复**:
- 任何状态都可以通过Esc安全退出
- 操作失败后保持当前状态
- 异常情况下自动恢复到安全状态
